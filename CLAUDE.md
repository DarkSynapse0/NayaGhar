## Project Overview

NayaGhar is a housing platform for rural-to-urban migrants (students, young professionals). It features AI-powered property matching via semantic search, interactive map-based search, verified listings, WhatsApp landlord communication, and a trust/review system. Designed for low-bandwidth/rural-friendly usage.

## Commands

```bash
# Development
npm run dev          # Start Next.js dev server (http://localhost:3000)
npm run build        # Production build
npm run start        # Start production server
npm run lint         # Run ESLint

# Database (Drizzle ORM)
npx drizzle-kit generate   # Generate migrations from schema changes
npx drizzle-kit migrate    # Apply migrations to database
npx drizzle-kit push       # Push schema directly (dev only)

# Embedding Service (Python FastAPI)
cd embedding-service
pip install -r requirements.txt
uvicorn main:app --reload --port 8000
```

## Architecture

### Two-service system

1. **Next.js 16 App (TypeScript)** — handles all frontend, API routes, auth, and CRUD. Uses App Router with Server Components by default.
2. **Python FastAPI microservice** (`embedding-service/`) — generates OpenAI embeddings for semantic search. Communicates with the Next.js app via HTTP (`/embed` endpoint).

### Key architectural decisions

- **PostgreSQL + pgvector** — single database for both relational data and vector similarity search. No separate vector DB. Hybrid queries combine `<=>` cosine distance with standard SQL `WHERE` filters in one query.
- **Drizzle ORM** — type-safe schema in `src/lib/db/schema.ts` is the single source of truth for all tables. Types are inferred from schema (not manually defined). Database access uses `getDb()` (lazy initialization) from `src/lib/db/index.ts`.
- **MapLibre GL JS** — open-source map rendering with vector tiles for low-bandwidth efficiency. Map bounding box syncs with search API for viewport-based queries.
- **WhatsApp Cloud API** — template messages connect tenants and landlords. No in-app chat; conversations happen natively in WhatsApp.
- **S3-compatible storage** (Cloudflare R2 / AWS S3) — property photos uploaded via presigned URLs.

### Data flow: Search

1. User query → `GET /api/search` with filters + optional natural language `q` param
2. If `q` exists: call embedding service → get vector → pgvector cosine similarity + SQL filters in one query
3. If no `q`: pure SQL filter query with optional bounding box for map viewport
4. Results returned with pagination cursor


### Database tables

All defined in `src/lib/db/schema.ts`:
- **users** — tenants, landlords, admins with trust scores and phone verification
- **listings** — properties with pgvector `embedding` column (1536 dims), coordinates, amenities (jsonb), photos (jsonb)
- **reviews** — ratings tied to listings, with verified-stay flag
- **pois** — points of interest (universities, transit, hospitals) for spatial proximity features
- **conversations** — WhatsApp conversation tracking for analytics

## Environment

Copy `.env.example` to `.env.local`. Required vars: `DATABASE_URL`, `EMBEDDING_SERVICE_URL`, `OPENAI_API_KEY`. See `.env.example` for all options.

## Design Constraints

- Target audience has low bandwidth (2G connections). Minimize JS shipped to client — prefer Server Components. Lazy-load images and map.
- All API responses follow `{ data, pagination?, error }` shape (see `src/types/search.ts`).
- Property types are: `room`, `apartment`, `pg`, `hostel`.
- Prices stored in smallest currency unit (paisa (1 NPR = 100 paisa)) as integers.
